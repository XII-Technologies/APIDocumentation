GitHub infrastructure modernization report

Initial audit date: 2026-10-18; cross-platform follow-up: 2026-10-19. Baseline commit: c1cad315e2eee4da62a16117d48ba661c946c81c. Initial implementation branch: TE/Maintenance; follow-up branch: TE/CI. The repository was initially clean. License and attribution were preserved.

1. Audit findings

  • The actual default branch is Development; original jobs also targeted main and dev. Two scheduled Windows workflows duplicated expensive work.
  • Original release scripts built Dev, used obsolete executable/shader names, ignored shader errors, and broadly deleted symbols and test data before packaging.
  • Formatting/copyright jobs modified contribution branches, used moving action references and unnecessary write credentials, and mishandled fork refs.
  • Clang-Tidy assumed an old LLVM download plus custom tools and did not reliably propagate findings as failures. No workflow/YAML quality gate existed.
  • CTest was integrated but lacked explicit hardware labels, complete-suite selection, isolated diagnostics, and reliable out-of-source asset discovery.
  • Qt 6.11 and x64 Windows/Linux DXC paths differ from old workflow assumptions. D3D12 is deliberately disabled. macOS platform files do not establish a usable whole-engine or test-framework build.
  • CONTRIBUTING was a placeholder, support referenced a nonexistent template, security promised a response deadline, and the README overstated platform support.
  • There is no validated binary SDK installation/distribution contract or complete generated SBOM. The existing license says All Rights Reserved, not an open-source grant.

2. Implemented improvements

CI and build integration. Added an isolated CPU build filter and CMake presets; preserved ordinary developer presets. A reusable native workflow builds and runs the actual Foundation/Core/ToolsFoundation suites through CTest. An explicit discovery check rejects missing/extra suites, including an empty selection. Debug, Dev and Shipping use the engine's native configuration names. C++23 fallback is disallowed. CTest receives the source SDK root, avoids saved test selection, runs shared-fixture suites serially, labels headless/hardware/interactive suites, and emits native JSON plus JUnit diagnostics without opening HTML or console UIs.

Efficiency and quality. Replaced duplicate nightly builds with a representative PR matrix and weekly extended checks. Added bounded compilation, cancellation, seven-day diagnostics, a bounded Linux compiler-object cache and no unused CPU submodule payloads. Added checksum-verified actionlint, ShellCheck integration, YAML lint, local documentation links, action-pin/permission contracts, and read-only changed-line formatting/copyright checks. Formatter errors fail and suggestions remain patches; filenames with spaces and .inl files are covered.

Security. All external actions have immutable commit pins. PR build jobs have read-only contents access, no publication secrets and no persisted Git credentials. CodeQL analyzes first-party C/C++ and Actions in build-free mode. Dependency review rejects newly introduced high/critical known dependency issues where GitHub's dependency graph supports them. Dependabot manages action and submodule revisions. The labeler is a metadata-only privileged PR job with no checkout or shell code. Security reporting retains the existing contact and adds conditional private GitHub reporting without invented deadlines or historical-version support guarantees.

Releases and auxiliary publication. Explicit matching numeric version tags, default-branch ancestry, Windows/Linux Shipping CPU checks and quality checks gate an attested, checksummed draft source release behind the release environment. Only the same run's fixed-name artifact enters the privileged job; engine code does not execute there. Source manifests preserve submodule identities without claiming to bundle them. API generation keeps artifact-only mode by default; optional reviewed publication uses a separately scoped environment token and a normal push. Precompiled tool automation builds an ArchiveTool Shipping candidate for review rather than force-pushing a broad collection into another repository.

Documentation and community. Rewrote README, CONTRIBUTING, SECURITY and SUPPORT; added authoritative build and infrastructure guides and this verification record. Updated the documentation index and coding-standard enforcement claims. Added a PR template, build/platform form and issue-form configuration; enriched bug reports and corrected malformed dropdown option values and stale labeler paths.

Validation-driven test repairs. Native execution exposed real issues, all fixed without disabling tests or weakening engine warning policies:

  • SDL-disabled screen/input/window stubs had unused parameters and a duplicate callback already implemented in common Core code.
  • TestFramework's JSON message-name table omitted an enum value, causing a final result serialization crash. A compile-time size check now prevents recurrence.
  • Generated Data/Base build directories shadowed source assets; CTest now passes an explicit source SDK root.
  • Process fixtures bypassed core-system startup, then failed during teardown. They now follow the normal startup/shutdown lifecycle.
  • A directory-watcher fixture assumed unobserved intermediate changes could not coalesce on ReFS. It now polls before recreating the deleted destination, still requiring all four events.
  • A logging expectation assumed development messages existed in Shipping. The expectation follows the compiled feature while retaining output assertions.

6. Remaining limitations

  • Establish the existing CodeQL findings baseline before making scans required. Build-free scanning cannot replace a successful native build. Weekly compiler analysis and protected release publication require their own execution evidence.
  • No GPU/editor runtime certification, sanitizer support, binary SDK, reproducibility guarantee or complete vendored-dependency CVE coverage is claimed.
  • Existing CMake SDK downloads still lack a comprehensive checksum policy; CPU CI avoids those downloads. Vendored dependencies need human updates and license review.
  • Broader precompiled editor/renderer tools require their own migration and runtime checks before external publication. Old Azure inputs remain historical and unvalidated; the new build guide is authoritative for supported procedures.
  • Formal community governance and a new license grant require project-owner decisions; neither contacts nor enforcement commitments were invented.

Build and Test matrix expansion

The primary workflow is now Build and Test, with the aggregate check Build and Test required. Debug, Dev and Shipping each run with Windows VS 2026 MSVC, Linux GCC 15, Linux Clang 22 / LLD 22, and macOS 26 ARM64 Apple Clang from the image's stable Xcode 26.6. This is twelve jobs, limited to six simultaneous builds. Clang Shipping moved out of extended validation because the primary matrix now covers it; weekly MSVC compiler analysis remains distinct.

The macOS preset reuses the CPU filter and existing Makefile platform support. The port repairs stale platform macros, supplies the existing non-Windows DirectXTex compatibility headers, uses Mach VM statistics, supports Darwin's semaphore API and correct CLI executable paths, and adds missing standard headers required by libc++. Existing capability flags remain explicit; no tests were disabled to obtain passing results. The fallback message-loop constructor now uses the declared implementation class.

Expanded validation exposed signed-zero bone hashes, a bit-exact Perlin regression that rejected optimized GCC output, and an assertion-only image variable rejected by Clang Shipping. The bone hash canonicalizes zero through integer bits. The Perlin test retains the six original reference hashes to verify its compact float32 reference fixture, then checks all 1,536 computed samples for finiteness and agreement within 1e-6. Noise uses normal unity compilation and compiler optimization settings; no per-source compiler overrides remain. The image check compiles its validation only in development configurations. Warning policies and failure propagation remain unchanged. New semaphore and executable-path checks cover the platform behavior repaired here.

An optimized GCC 15 reproduction matched the six failing CI hashes; its maximum sample error against the original reference was 5.96046448e-8 (one float rounding step). The numerical test preserves every sample while tolerating that rounding. The Windows Dev run also exposed a double-vector cone assertion that compared a float-returning angle API against double precision. Those three tests now check the cone directly with double dot products and cosines, retain 100,000 samples per axis, and use fixed seeds for reproducible regression coverage.

Local VS 2026 Shipping and Dev builds each passed FoundationTest, CoreTest and ToolsFoundationTest. Hosted macOS Debug built and passed those same suites in the focused platform validation. The temporary port-validation workflow has been removed; required coverage lives in the primary matrix.
