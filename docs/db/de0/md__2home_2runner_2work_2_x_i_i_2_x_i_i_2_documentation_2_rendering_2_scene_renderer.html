Default Scene and Editor rendering

Data/Base/RenderPipelines contains two default authored resources: Scene and Editor, plus independently authored SceneAtmosphere and SceneDirectionalShadows, SceneSpotShadows, SceneScreenSpaceReflections, SceneScreenSpaceIrradiance, SceneTransparency and SceneParticles workloads composed by Scene. Directional and spotlight shadows reuse SceneShadowCascade for each cascade's caster rasterization. The two roots are defaults, not an enumeration of supported workloads. Applications can select any compatible resource or construct a resource descriptor in C++. Both paths use the same compiler, pipeline instances and render graph.

Consolidation decisions

The hierarchical compiler from PR #429, world-authoritative extraction from #430, native operations from #432 and resource/view runtime from #438 remain the common infrastructure. The missing integration was a dependable default composition and its consumers:

  • Empty default world/Editor profile selections and the fragment collection did not establish an application rendering path. Scene now owns that authored path; Editor composes it through an ordinary resource reference.
  • Root interfaces did not receive view-owned external targets. ViewTarget now provides that explicit boundary; other interfaces retain caller-owned semantics.
  • Subgraph expansion synthesized output resolution constraints, including for buffers. It now preserves only authored texture constraints, allowing real composition and scaled views to retain their native pin contracts.
  • The sample separately coordinated visibility, shadows, sensor and presentation fragments. It now exercises ordinary world/view execution and checks its result.
  • The fixed preview assets and texture-allocation-only operation duplicated engine-owned definitions or graph responsibilities. Normal C++ resource descriptors and resource-producing operations replace those dependencies.

The broad GPU run also exposed a GAL lifetime regression: independently retained objects used the device's internal allocator although they can destroy the last reference to that device during their own destructor. GetAllocator() now returns the existing parent allocator, honoring its documented lifetime contract. Internal device helpers retain their tracking allocator. The existing last-buffer-view lifetime regression exercises the failure directly.

Implemented path

Scene renders world mesh components through shared GPU instance extraction, view-local visibility and LOD selection, indirect vertex-pull draws, reversed-Z depth, material G-buffer rasterization, directional and clustered analytical local lights, optional world directional and spotlight shadows, ambient diffuse and emission, spatial ambient visibility, local probe specular and optional screen reflections, world atmosphere, single-bounce screen-space diffuse transport, transparent mesh and ballistic billboard layers and temporal antialiasing, exposure, tone mapping, color grading and presentation. It does not require mesh shaders or ray tracing. Material loading and shader failures remain errors; a clear output is not evidence of scene rendering.

Scene surface images are viewport-local. Atmospheric lookup images have their own authored dimensions. The root ViewTarget input receives the view's external render target or current swapchain image. Presentation applies the window viewport offset, scales the rendered image and preserves pixels outside that rectangle. InputCandidates remains an optional geometry input. Outputs including SceneDepth, ObjectId, HDRSceneColor and GradedColor are explicit interfaces for composition and inspection.

Opaque material lighting semantics

Canonical unlit surfaces and materials with ReceivesLighting disabled write sampled base RGB plus emission into the existing emissive target. Ambient, directional, clustered local, environment-specular and screen-reflection receivers skip these surfaces; they still write ordinary depth, normals, albedo, IDs and velocity and can appear in another surface's reflection. Forward transparent unlit semantics remain unchanged.

world geometry/materials -> G-buffer -> packed lighting policy -> ambient/direct/specular/SSR
+-> sampled emission + unlit base -----------+-> HDR composition
-> atmosphere/layers/TAA/display

The RGBA8 material target retains roughness, metallic and specular in RGB. Its alpha is an explicitly packed evaluated-surface byte: bit 0 means unlit; bits 1 through 7 retain their runtime low-feature meanings, including transmission at bit 6 and sheen at bit 7. The normal-texture flag is replaced because normal sampling has already produced the G-buffer normal. Higher runtime flags never saturate this byte and accidentally enable unrelated features. External producers of these material images must use this packed contract, rather than truncating or saturating the full runtime material flag word. The shared shader helper is Shaders/Pipeline/GBufferMaterial.h. No target format, allocation or root interface changes are needed. The retained ReSTIR shader consumers also reject unlit receivers; shader compilation does not certify that optional algorithm.

NativeScenePipeline/OpaqueMaterialLightingAndPackedFlags reads production HDR, ambient/direct light, emission, packed material and object identity through ten phases with real geometry, a sun and a point light. Changing both light intensities changes lit output but leaves unlit final images exactly equal. Unlit HDR equals the actual emissive target and sampled authored color, including a base texture; all direct and ambient energy is zero. Removing ReceivesLighting matches explicit Unlit. GPU byte readbacks verify absent features, baked normal textures, transmission and sheen without spurious low bits, and restoring the original material restores the exact final image. Scene reflection acceptance additionally changes a known reflecting floor to unlit: floor hits and energy become zero, then restore when the lit mirror returns. Other surfaces continue reflecting it normally.

Production RendererAssets exports all eight source assets deterministically on two runs; EditorDocuments (20) and NodeLayout (3) also pass. The production compiler successfully compiles indexed/mesh G-buffer and both retained ReSTIR shader consumers for VK_SM66 and exits zero, but logs file-access errors during sandboxed shutdown. Other backends and optional ReSTIR runtime behavior remain unverified. Final Debug build checks cover GraphicsCore, both graphics test executables, both Editor test executables and GpuDrivenScene. Editor references Scene and disables that occurrence's presentation through an ordinary reflected property override. It adds filtered world surface queries for mesh picking and selected-only, including occluded, selection; material/depth visualization; shape icons and their asynchronous picking; and debug drawing. The final Editor operation presents after these overlays. Picking resolves captured GPU identities against live world object/component handles. Meshes and materials in scene-dependent previews use the asset profile's main pipeline selection.

Display-linear color grading declares render-target usage as well as compute and sampling usage, allowing these overlays to compose on the actual Scene output. Overlay images remain viewport-local; window-coordinate picking maps into their captured extents, including a scaled or offset view.

The default render scale is stable. Dynamic-resolution feedback is opt-in through the existing minimum/maximum scale CVars. Unavailable GPU timings do not substitute CPU loading time, and native resolution preserves odd dimensions and one-pixel views.

Ownership and failure contracts

  • Worlds and components own scene state. The render world module extracts demanded categories and synchronizes derived GPU instances and light records.
  • Resource descriptors own immutable definitions. Compilations share definitions; pipeline instances own mutable pass objects, parameters and temporal state.
  • Interfaces carry resources. Expanding a subgraph preserves authored resolution constraints; it does not invent constraints on buffer outputs or force all images to viewport resolution.
  • Operations declare the resources they produce. CreateTexturePass is removed. The existing ClearTexture operation declares and clears a graph transient; ClearColor still clears a supplied target. Allocation, versions, barriers and retirement remain graph/GAL responsibilities.
  • The GameEngine loading/missing fallback is an ordinary C++ resource descriptor containing ClearTexture and Present. Missing resources produce a diagnostic; GetResourceAcquireResult() distinguishes fallback acquisition from the selected resource. Compilation/build errors are not replaced by a successful scene result.
  • xiiView::GetLastRenderResult() reports the world's latest build/submission attempt. Success does not mean GPU completion. Sample error exits inspect this result and require a final selected resource.

Fixed texture and cubemap previews are registered from C++ by xiiTexturePreviewPass::GetPipelineResource. They use the normal resource compiler and view runtime. Explicit per-view overrides remain supported; no SDK preview asset duplicates these definitions.

The asset profile exposes one Main Render Pipeline reference, defaulting to Scene. Applications, remote views and scene-dependent previews use this selection. Interactive Editor scenes select the canonical Editor resource directly, and fixed texture/cubemap utilities use their C++ descriptors. Explicit view references still take precedence. Pipeline assets retain their authored Settings object and execution contracts.

Profile version 3 serializes only the main reference. Version-1 GamePipeline and version-2 ScenePipeline values migrate to MainRenderPipeline; the former empty version-1 world default selects Scene. Version-2 explicit empty selections remain empty. Retired Editor/preview profile selectors are discarded. An empty or invalid main selection remains diagnosable. Migration handles Objects-only profile DDL as well as files carrying an explicit legacy type table.

Conventional spotlight shadows

Scene composes the independently authored SceneSpotShadows workload. Its only new native operation, xiiSpotShadowPass, selects shadow-casting spotlights from the authoritative extracted light packets and reuses xiiLocalShadowAtlasBuilder for perspective projections. It does not schedule features in xiiView.

Scene geometry uploads ------------------------------------+
World Spotlights -> SpotShadows snapshot -> ShadowAtlas ----+-> SceneShadowCascade x4
| | (perspective caster views)
+-> opaque local lighting <--------+--- completed atlas
+-> transparent raster <--------------- completed atlas
opaque local potential shadow contribution -> ReactiveLighting union -> TAA
screen-space irradiance ---------------------> ReactiveLighting union

Each reused caster occurrence selects world/tag-authoritative geometry, performs GPU instance/meshlet culling, resets counters, prepares indirect vertex-pull draws and rasterizes the current material/pose into its own atlas rectangle. Casters outside the main camera remain eligible. CascadeIndex selects the occurrence's slot for either snapshot type; the spotlight path uses perspective position, cone rejection and LOD rather than substituting a directional projection. Alpha-masked materials use the existing depth shader's actual texture/cutoff. Transparent meshes remain receivers rather than shadow casters.

The snapshot carries one to four views, a graph-owned 384-byte sampling constant buffer, and a structured SRV receiver table of sorted (object ID, flags) pairs, eight bytes per world instance (one zero sentinel when empty). The atlas is single-sample D32Float with DepthStencil/SRV bindings. At the authored 1,024-pixel tile resolution, one light uses 1,024 squared, two use 2,048 by 1,024, and three or four use 2,048 squared (4/8/16 MiB respectively). Caster writes explicitly precede each subsequent atlas version and both opaque/transparent consumers. Sampling validates the exact dimensions, format, bindings and buffer layouts.

Opaque local lighting resolves receiver flags through the G-buffer's R32UInt ID; transparent lighting carries instance flags through its vertex interface. Both multiply only the matching spotlight's BRDF contribution by four-comparison PCF visibility. Other local lights, ambient illumination and emission retain their contributions. Sampling clamps taps to the selected tile, rejects out-of-frustum coordinates, and applies reversed-Z depth and world/texel normal bias. Scene authors depth bias 0.00005 for this perspective path. Reflected settings retain Enabled, Resolution, MaximumLights, NearPlane and all sampling biases.

Only extracted positive-intensity spotlights with CastShadows participate. ShadowFadeOutRange zero resolves to the light's effective range, as specified by the light component API. Shadows fade over the final twenty percent of the camera/light distance and disappear beyond that range. With no eligible light, or Enabled false, no atlas, sampling buffers or reactive image are produced and the existing unshadowed lighting variant executes. Positive-range cones must be finite, between 1 and 175 degrees, and extend beyond twice NearPlane. More than the authored MaximumLights (at most four), stereo views, missing active resources or oversized device atlas dimensions fail explicitly; no unrelated shadow algorithm or silent light truncation replaces them. Point and area lights remain unshadowed in this workload.

The shadowed opaque shader also writes an optional viewport-sized RGBA16Float SRV/UAV image (eight bytes per pixel). It marks potential incident spotlight contribution before applying visibility, including fully shadowed receivers. TAA therefore rejects stale history on both shadow/light changes and disappearance. The existing RadianceAdd operation now accepts either optional input for the irradiance/reactivity union: neither produces no output, one forwards its handle, and both execute the existing RGBA32Float addition. Forward transparent layers retain their existing conservative history-trust path. Independent pipeline occurrences own configuration and history; recorded callbacks retain snapshots and GAL resources without borrowing the world or operation instance.

SceneSpotShadows/PerspectiveCasterAtlasAffectsIndividualLights compares actual Scene GPU images and buffers. Twenty-six analytical phases cover caster/material and light removal, alpha-mask textures, automatic/explicit shadow fading, main camera cuts, odd resize, reload, a one-pixel viewport and exact restoration. Initially 128 final pixels change; an off-camera caster affects 1,928 shadowed pixels while its identity is absent from the main image. Two independently shadowed lights sum correctly, and four lights exercise every tile in the 2-by-2 atlas with the expected doubled two-light result. Atlas depths, sampling matrices, light indices and receiver records are read back. Every HDR delta equals the measured per-light change; depth, IDs and ambient light match the disabled view. Four transparent phases change 81 layer pixels and 185 final pixels, with no layer change for an unlit receiver or a material that cannot cast shadows. Eleven temporal phases interleave two worlds/four views, verify initialization, cuts, resize, reload and motion, and check 5,415 disappeared interior pixels against a current-frame reference. A recording executes after its world and pipeline instance are destroyed. Active missing atlas/capacity errors fail the view, their explicitly disabled counterparts succeed, and the atlas rejects an actual device-dimension overflow before allocation. Editor's nested override produces the same final pixel changes as Scene and restores output exactly: 128 pixels without screen irradiance, and 312 with irradiance enabled, exercising the combined reactive-input composition.

Bloom and metered exposure

The existing Scene display chain is an actual rendering workload. It remains in the canonical resource rather than introducing a second display manager or a subgraph with no additional reusable boundary:

HDRSceneColor -> automatic Luminance Histogram -> Auto Exposure --+
Camera exposure -> manual two-float upload -----------------------+
+-> TAA -> Upscale -> optional Bloom ------------------+-> Tone Mapping -> Grading -> Present
+-----------------------------------+

Histogram input is readable single-sample RGBA; its output is a graph-owned structured 256-uint SRV/UAV buffer (1,024 bytes). The producer clears counters, then counts every input pixel into log-luminance bins. Adaptation validates this exact layout in automatic mode and imports its own two-float SRV/UAV exposure/average-luminance buffer. Valid history is an explicit read-modify-write dependency. Resolved manual mode omits histogram buffers, constants and dispatch. It uploads compensated camera exposure and zero average luminance into an eight-byte graph-owned SRV buffer, without loading or dispatching adaptation. The upload owns its snapshot across delayed execution and owner destruction. Returning to automatic mode restarts adaptation from current metering; automatic mode clips authored percentiles, reconstructs bin centers and adapts toward the metered exposure. Fractional percentile weights remain fractional for one-pixel viewports. First frames do not read uninitialized previous exposure.

Bloom extracts HDR luminance above the reflected threshold with a soft knee and a normalized nine-sample tent footprint. Up to five reductions build a six-level RGBA16Float pyramid, using ceiling half extents and clamping narrow dimensions to one. Reconstruction combines each fine level with the coarser result using equal weights. Every reduction filter and reconstruction combination has unit weight, so constant radiance does not increase with the number of levels. BloomRadius controls the tent footprint in each source level's texels; the coarse levels produce a wider glow than a full-resolution-only kernel. Zero radius records extraction only. Output remains input-sized in Scene. Each stage declares its own reads and transient write through the existing graph; there are at most eleven compute stages and no CPU readbacks or additional persistent state. With resolved BloomStrength zero, the operation produces no bloom image and records no bloom dispatch. Tone mapping accepts the absent input only at zero strength and uses a zero-weight HDR binding for that shader slot; the shader bypasses its sample. Active missing bloom remains a view failure. These operations validate dimensions, formats, binding flags and dispatch bounds; binding failures report failure before dispatch.

Multiscale acceptance reads the actual Scene HDR, bloom and final images. It verifies a halo more than ten pixels beyond the source bounds, zero-radius and zero-strength stage elimination, deterministic resize/reload behavior, and uniform-field energy at 9x11, 65x1, 1x65 and 1x1 extents. The existing final-pixel exposure/tone-map/transfer oracle still passes. In the small acceptance workload, the existing GPU timestamp profiler measured 0.0072–0.0095 ms per bloom stage across 11–13 available samples; these are mixed small-view pass measurements, not a representative frame-time baseline or a measured speedup.

Tone mapping adds bloom to HDR before exposure and maps that result to display-linear color. Existing grading and presentation apply afterward. Controls remain reflected or per-view display settings, and independent occurrences own their configuration/history. This change preserves Scene/Editor identities, existing root interfaces and the ten-source asset library; only Scene's native pin metadata describes optional bloom and histogram resources.

SceneDisplay/BloomAndMeteredExposureAffectProductionOutput exercises actual opaque emissive geometry and production Scene resources. Thirteen bloom phases verify threshold/knee, radius, zero strength, removed content, odd resize, orthographic projection, reload and exact restoration. Initially 784 final pixels change, including 208 pixels outside the bright source. Radius zero removes that halo. Every enabled final RGB value matches measured GPU HDR/bloom inputs, exposure, tone mapping and presentation within output precision. HDR remains identical between enabled and disabled views.

Nine metering phases verify manual/automatic independent views, one-pixel initialization, frozen adaptation, camera cuts, reload, resize and both nonzero adaptation rates against deterministic clock steps. Histogram totals equal the actual pixel count, and presented pixels match the measured exposure. Four additional phases exercise manual/automatic transitions, compensation and a runtime display override. Scene and inherited Editor graph resources confirm the absence of histogram/adaptation allocations in manual mode. Standalone manual graphs need no histogram input; two retained recordings execute in reverse order after owner destruction with distinct correct exposure values. The test reproduced luminance 512 being metered as 425.48 in a one-pixel viewport; corrected fractional weights and bin decoding yield 503.68 within quantization error. Active missing bloom and a four-byte histogram fail the view; zero bloom strength permits the absent bloom input. Editor composition changes 4,780 matching final pixels for bloom and 10,015 for automatic exposure, with exact restoration.

Windows/MSVC Debug builds pass GraphicsCore, both graphics test executables, both Editor test executables and GpuDrivenScene. Complete GraphicsCoreTest (81), Vulkan GraphicsFoundationTest (141) and Vulkan EditorEngineProcessFrameworkTest (76) subtests pass. The strengthened final bloom composition readbacks also pass the focused SceneDisplay run. RendererAssets exports all ten sources deterministically on repeated runs; EditorDocuments (20), NodeLayout (3) and the rebuilt 300-frame Vulkan Scene sample pass. Existing Qt font and unused Vulkan output warnings remain. Generated pipeline binaries, caches and unrelated scene edits are excluded.

This certifies the bounded spatial tent bloom and existing log-histogram exposure path. Anisotropic bloom, lens dirt, representative performance, HDR monitor calibration, stereo and other backends remain unverified. Manual exposure uses a transfer upload with no metering or adaptation dispatch. Arbitrary retained automatic exposure recordings across intervening submissions remain separate acceptance work; existing epoch and world-destruction recording regressions pass.

Ambient visibility

Scene connects its actual depth and material normals to xiiAmbientOcclusionPass with UseRayTracing=false. xiiAmbientOcclusionTemporalPass runs with UseHistory=false to perform only edge-aware spatial filtering. Its StableAO feeds the existing optional Occlusion input of diffuse surface lighting. The normal HDR combination, display operations and Editor composition consume the result. Root outputs retain their contracts; optional AmbientOcclusion exposes the visibility mask for inspection.

Resource Producer and format Consumer
SceneDepth DepthRaster, reversed-Z D32Float at render resolution AO reconstruction and spatial edge rejection
NormalRoughness GBufferRaster, RGBA8UNormalized AO world-space hemisphere sampling
Normal GBufferRaster, RG16SNormalized octahedral normals Spatial edge rejection
RawAO AmbientOcclusion, R8UNormalized SRV/UAV Spatial filter
StableAO Spatial filter, R8UNormalized SRV/UAV DiffuseSurfaceLighting.Occlusion

Both masks are graph transients at the current render resolution. The spatial path allocates no surface history, readiness fences or retained mask images. Sampling uses a fixed spatial phase and reconstructs neighbours at their actual texel centers. The radius is in world units; pixel stride and sample counts control the screen-space search. Scene authors radius 2, pixel stride 2, eight directions, four steps and full spatial weighting. Other tuning remains reflected on the two existing operations.

Setting the AO occurrence's Enabled=false publishes an absent optional mask. The filter emits no work for that absence, and diffuse lighting preserves its unoccluded result. It does not suppress direct lighting, emission or authored material occlusion. R8 storage requires TextureUAVExtendedFormats; an enabled path reports an explicit build failure when that capability is unavailable. An authored disabled occurrence is the supported fallback, with no replacement algorithm selected implicitly.

This integration is screen-space ambient visibility, with the usual missing offscreen and hidden geometry. It is not ray-traced visibility or indirect light transport. Spatial filtering remains the default. Setting the filter occurrence's UseHistory=true opts into temporal accumulation using Scene's existing explicit temporal camera and G-buffer motion producer. The filter validates camera extent, previous-frame identity and consecutive camera history before sampling old masks. The previous surface depth is tested in its own camera basis, reconstructed from the current world position; camera translation does not compare unrelated view depths. Current neighbourhood clipping bounds accumulated visibility. Raster motion deliberately excludes projection jitter. AO's raw mask and surface histories instead follow the previous raster grid, so their history UV adds the previous-minus-current jitter offset before either image is sampled. This keeps AO reprojection aligned with SSR surface histories while TAA retains its stable resolved-color grid. TAA retains an additional R8 provenance image when ambient visibility is present. A currently unoccluded pixel rejects color history carrying old occlusion; stable occluded pixels still accumulate. The last provenance image is consumed once when the AO input disappears, then released from active use. This prevents disappeared occluders from leaving resolved darkening on an unchanged receiver. The optional provenance path requires extended storage formats and adds one byte per pixel to each participating TAA history slot.

Each temporal occurrence owns at most eight mask/surface slots. Graph snapshots retain both consumed and produced slots. GPU completion and exclusive slot ownership are both required for reuse; exhausted retained recordings report an explicit capacity failure. Imports resolve their native state at execution, and history publication propagates readiness to every consumer queue. Revisions and monotonic frame publication prevent old recordings from restoring invalidated or newer state. Spatial filtering allocates none of this persistent storage.

RawAmbientOcclusion, AmbientOcclusionHistory and AmbientOcclusionSurface provide optional resource inspection alongside the final visibility mask.

Scene and authored Editor acceptance compare temporal, spatial and disabled visibility across independent worlds. Readbacks verify neighbourhood bounds, previous-mask identity, camera dolly/pan, moved and removed geometry, orthographic projection, camera cuts, resize and reload. A CPU camera-space oracle checks numerical history blending on more than a thousand rendered surface reprojections per motion phase, including pixels whose previous and current view depths differ. Eight retained native recordings execute in reverse after world destruction; a ninth reports the explicit capacity limit. Combined jittered TAA/AO acceptance also uses the exact rendered camera snapshots, matching per-view Halton sequences, pre/post reconstruction HDR readbacks and a numerical jitter-aware history oracle. The regression fails against the jitter-free AO history lookup. Scene and Editor both cover camera motion, cuts, resize/reload, moved and removed occluders and orthographic projection while reconstruction remains enabled. Animation-specific visibility, stereo and representative quality/performance remain acceptance work.

Vulkan acceptance uses a material-bearing cube contacting a real floor, a world directional light and manual exposure. Full image readbacks compare AO enabled and disabled: depth and direct illumination are identical, ambient diffuse equals the unoccluded result multiplied by the mask, and the HDR delta equals the ambient delta. At 129 by 97, 492 final pixels change and minimum visibility is 189/255. Deleting the occluder restores a neutral mask and identical final images while the second world's contact occlusion remains active. Odd resizing, resource reload, camera-history invalidation and independent views/worlds are exercised.

World atmosphere

SceneAtmosphere.xiiRenderPipelineAsset is a reusable physical atmosphere workload, referenced by its source GUID from Scene. Its four operations are world atmosphere constants, transmittance integration, approximate multiple scattering and per-pixel sky/aerial application. Scene supplies the actual depth, opaque HDR, camera snapshot and selected directional illumination. Its output replaces HDR before histogram/exposure, bloom, tone mapping and the public HDRSceneColor interface. Editor consumes this same Scene output before its overlays. Scene's public HDR interface retains its RGBA32Float SRV/UAV contract through an authored requirement on this subgraph occurrence. Other uses of the workload can retain the inactive application's input format.

Lookup images declare SRV/UAV usage and remain graph-owned, occurrence-local transients. They regenerate when the workload executes; no global LUT registry or content cache is introduced. Valid constants with a missing or malformed LUT remain an explicit build failure.

Component physical coefficients, planet/up/altitude, sun parameters and sample counts remain reflected. Lookup dimensions and queue selection remain independent pass properties. The implementation integrates Rayleigh/Mie scattering and absorption along sky and geometry segments, with ozone extinction and the existing solar disk. Orthographic cameras use parallel rays from their pixel's camera plane. This path does not supply environment convolution, atmospheric shadows, clouds or participating-volume lighting; approximate multiple scattering and bounded ray marching are explicit quality limits.

Triangle power is world-space area times Rec. 709 luminance of the untextured material emission factor. Emissive next-event sampling and diffuse MIS

RayTracedIrradiancePass.EmissiveLightSamples accepts zero through eight emitter queries per path vertex. The proposal mixes 95 percent hierarchical power sampling with five percent uniform triangle selection. World geometry for diffuse probe updates

On the non-hardware-ray GI path, the authored Scene and Editor pipelines can trace scheduled directional probe rays against the current view's world mesh records. This includes objects outside the camera frustum and respects view tags. The update reuses the canonical geometry and material buffers. A hit can return emissive material radiance, including emissive texture and cutout coverage, or reuse scene radiance where the first hit matches the camera depth.
