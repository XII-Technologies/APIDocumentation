Default Scene and Editor rendering

Data/Base/RenderPipelines contains two default authored resources: Scene and Editor, plus independently authored SceneAtmosphere and SceneDirectionalShadows, SceneSpotShadows, SceneScreenSpaceReflections, SceneScreenSpaceIrradiance, SceneTransparency and SceneParticles workloads composed by Scene. Directional and spotlight shadows reuse SceneShadowCascade for each cascade's caster rasterization. The two roots are defaults, not an enumeration of supported workloads. Applications can select any compatible resource or construct a resource descriptor in C++. Both paths use the same compiler, pipeline instances and render graph.

Consolidation decisions

The hierarchical compiler from PR #429, world-authoritative extraction from #430, native operations from #432 and resource/view runtime from #438 remain the common infrastructure. The missing integration was a dependable default composition and its consumers:

  • Empty default world/Editor profile selections and the fragment collection did not establish an application rendering path. Scene now owns that authored path; Editor composes it through an ordinary resource reference.
  • Root interfaces did not receive view-owned external targets. ViewTarget now provides that explicit boundary; other interfaces retain caller-owned semantics.
  • Subgraph expansion synthesized output resolution constraints, including for buffers. It now preserves only authored texture constraints, allowing real composition and scaled views to retain their native pin contracts.
  • The sample separately coordinated visibility, shadows, sensor and presentation fragments. It now exercises ordinary world/view execution and checks its result.
  • The fixed preview assets and texture-allocation-only operation duplicated engine-owned definitions or graph responsibilities. Normal C++ resource descriptors and resource-producing operations replace those dependencies.

The broad GPU run also exposed a GAL lifetime regression: independently retained objects used the device's internal allocator although they can destroy the last reference to that device during their own destructor. GetAllocator() now returns the existing parent allocator, honoring its documented lifetime contract. Internal device helpers retain their tracking allocator. The existing last-buffer-view lifetime regression exercises the failure directly.

Implemented path

Scene renders world mesh components through shared GPU instance extraction, view-local visibility and LOD selection, indirect vertex-pull draws, reversed-Z depth, material G-buffer rasterization, directional and clustered analytical local lights, optional world directional and spotlight shadows, ambient diffuse and emission, spatial ambient visibility, optional world atmosphere, spatial screen reflections, transparent single-bounce screen-space diffuse transport, mesh and ballistic billboard layers and temporal antialiasing, exposure, tone mapping, color grading and presentation. It does not require mesh shaders or ray tracing. Material loading and shader failures remain errors; a clear output is not evidence of scene rendering.

Scene surface images are viewport-local. Atmospheric lookup images have their own authored dimensions. The root ViewTarget input receives the view's external render target or current swapchain image. Presentation applies the window viewport offset, scales the rendered image and preserves pixels outside that rectangle. InputCandidates remains an optional geometry input. Outputs including SceneDepth, ObjectId, HDRSceneColor and GradedColor are explicit interfaces for composition and inspection.

Opaque material lighting semantics

Canonical unlit surfaces and materials with ReceivesLighting disabled write sampled base RGB plus emission into the existing emissive target. Ambient, directional, clustered local, environment-specular and screen-reflection receivers skip these surfaces; they still write ordinary depth, normals, albedo, IDs and velocity and can appear in another surface's reflection. Forward transparent unlit semantics remain unchanged.

world geometry/materials -> G-buffer -> packed lighting policy -> ambient/direct/specular/SSR
+-> sampled emission + unlit base -----------+-> HDR composition
-> atmosphere/layers/TAA/display

The RGBA8 material target retains roughness, metallic and specular in RGB. Its alpha is an explicitly packed evaluated-surface byte: bit 0 means unlit; bits 1 through 7 retain their runtime low-feature meanings, including transmission at bit 6 and sheen at bit 7. The normal-texture flag is replaced because normal sampling has already produced the G-buffer normal. Higher runtime flags never saturate this byte and accidentally enable unrelated features. External producers of these material images must use this packed contract, rather than truncating or saturating the full runtime material flag word. The shared shader helper is Shaders/Pipeline/GBufferMaterial.h. No target format, allocation or root interface changes are needed. The retained ReSTIR shader consumers also reject unlit receivers; shader compilation does not certify that optional algorithm.

NativeScenePipeline/OpaqueMaterialLightingAndPackedFlags reads production HDR, ambient/direct light, emission, packed material and object identity through ten phases with real geometry, a sun and a point light. Changing both light intensities changes lit output but leaves unlit final images exactly equal. Unlit HDR equals the actual emissive target and sampled authored color, including a base texture; all direct and ambient energy is zero. Removing ReceivesLighting matches explicit Unlit. GPU byte readbacks verify absent features, baked normal textures, transmission and sheen without spurious low bits, and restoring the original material restores the exact final image. Scene reflection acceptance additionally changes a known reflecting floor to unlit: floor hits and energy become zero, then restore when the lit mirror returns. Other surfaces continue reflecting it normally.

The correction passes Windows/MSVC Debug validation and complete GraphicsCoreTest (81 subtests), Vulkan GraphicsFoundationTest (138) and EditorEngineProcessFrameworkTest (76). Production RendererAssets exports all eight source assets deterministically on two runs; EditorDocuments (20) and NodeLayout (3) also pass. The production compiler successfully compiles indexed/mesh G-buffer and both retained ReSTIR shader consumers for VK_SM66 and exits zero, but logs file-access errors during sandboxed shutdown. Other backends and optional ReSTIR runtime behavior remain unverified. Final Debug build checks cover GraphicsCore, both graphics test executables, both Editor test executables and GpuDrivenScene. The strengthened depth/identity assertions pass in the final native Scene group; the rebuilt Vulkan sample explicitly completes 300 frames. No generated pipeline binary or unrelated scene edit is committed.

Editor references Scene and disables that occurrence's presentation through an ordinary reflected property override. It adds filtered world surface queries for mesh picking and selected-only, including occluded, selection; material/depth visualization; shape icons and their asynchronous picking; and debug drawing. The final Editor operation presents after these overlays. Picking resolves captured GPU identities against live world object/component handles. Meshes and materials in scene-dependent previews use the asset profile's main pipeline selection.

Display-linear color grading declares render-target usage as well as compute and sampling usage, allowing these overlays to compose on the actual Scene output. Overlay images remain viewport-local; window-coordinate picking maps into their captured extents, including a scaled or offset view.

The default render scale is stable. Dynamic-resolution feedback is opt-in through the existing minimum/maximum scale CVars. Unavailable GPU timings do not substitute CPU loading time, and native resolution preserves odd dimensions and one-pixel views.

Ownership and failure contracts

  • Worlds and components own scene state. The render world module extracts demanded categories and synchronizes derived GPU instances and light records.
  • Resource descriptors own immutable definitions. Compilations share definitions; pipeline instances own mutable pass objects, parameters and temporal state.
  • Interfaces carry resources. Expanding a subgraph preserves authored resolution constraints; it does not invent constraints on buffer outputs or force all images to viewport resolution.
  • Operations declare the resources they produce. CreateTexturePass is removed. The existing ClearTexture operation declares and clears a graph transient; ClearColor still clears a supplied target. Allocation, versions, barriers and retirement remain graph/GAL responsibilities.
  • The GameEngine loading/missing fallback is an ordinary C++ resource descriptor containing ClearTexture and Present. Missing resources produce a diagnostic; GetResourceAcquireResult() distinguishes fallback acquisition from the selected resource. Compilation/build errors are not replaced by a successful scene result.
  • xiiView::GetLastRenderResult() reports the world's latest build/submission attempt. Success does not mean GPU completion. Sample error exits inspect this result and require a final selected resource.

Fixed texture and cubemap previews are registered from C++ by xiiTexturePreviewPass::GetPipelineResource. They use the normal resource compiler and view runtime. Explicit per-view overrides remain supported; no SDK preview asset duplicates these definitions.

The asset profile exposes one Main Render Pipeline reference, defaulting to Scene. Applications, remote views and scene-dependent previews use this selection. Interactive Editor scenes select the canonical Editor resource directly, and fixed texture/cubemap utilities use their C++ descriptors. Explicit view references still take precedence. Pipeline assets retain their authored Settings object and execution contracts.

Profile version 3 serializes only the main reference. Version-1 GamePipeline and version-2 ScenePipeline values migrate to MainRenderPipeline; the former empty version-1 world default selects Scene. Version-2 explicit empty selections remain empty. Retired Editor/preview profile selectors are discarded. An empty or invalid main selection remains diagnosable. Migration handles Objects-only profile DDL as well as files carrying an explicit legacy type table.

Consolidation and validation boundary

The ninety old SDK fragment asset/binary pairs are retired. Operation-level GPU and authoring tests construct their own resource descriptors; they do not require an installed fragment library. Canonical asset tests load the actual Scene and Editor sources, export them through the production compiler, compare repeated export bytes, and validate their interfaces. The GPU-driven sample uses its real world/view update and a selected resource; it has no custom graph builder or manual component extraction.

Vulkan regression coverage exercises actual geometry/material/lighting pixels, depth, object IDs and bindless base-color texture sampling, output transfer, resource reload, world destruction, independent worlds/views, resizing, offset/scaled presentation and pixels outside the viewport. The canonical Editor test compares its unobstructed output with Scene, checks visible/occluded selection and front-surface picking, switches resources, resizes and checks icon picking. Fixed preview tests exercise real texture/cubemap output. The sample has completed 300 Vulkan frames at 1440 by 810 through Scene.

These defaults intentionally exclude point/area/virtual/ray shadows, offscreen or multibounce GI, environment/probe reflections and advanced particle graph rendering. Spatial screen reflections, screen-space diffuse transport and temporal antialiasing are authored but opt-in. Other retained operations and focused tests are not certification of complete production techniques. Custom material shader permutations beyond the canonical GPU surface model, stereo rendering, backend coverage beyond the configured Vulkan build, large-scene performance and a complete interactive Editor acceptance session remain separate verification work. Automated engine/Editor GPU execution does not establish those claims.

Compiled .xiiBinRenderPipeline files are generated output and must never be committed. The Editor transforms the authored sources into its normal Data/Base/AssetCache/Common/RenderPipelines cache; profile defaults and the Editor subgraph reference use the source asset GUIDs through the existing lookup table. For standalone GPU tests/sample preparation, run EditorFrameworkTest -noGui -run -close -all -filter RendererAssets -outputDir <project-local-test-output>. This exports all ten sources with the production compiler into the ignored cache, checks stable exports and contracts, and is the CTest fixture for the GPU suites. The standalone sample mounts that cache; a missing transformation remains a loading failure rather than generating a substitute renderer. Core CPU tests require no transformed assets or Editor dependency.

If a preview reports a missing pipeline GUID, check Main Render Pipeline in Asset Profiles against the actual asset. Retired or deleted selections remain errors; they are not silently replaced by Scene. Applying the profile writes its matching runtime configuration. A stale runtime profile can otherwise retain an old selection even when the current profile schema has changed.

Conventional spotlight shadows

Scene composes the independently authored SceneSpotShadows workload. Its only new native operation, xiiSpotShadowPass, selects shadow-casting spotlights from the authoritative extracted light packets and reuses xiiLocalShadowAtlasBuilder for perspective projections. It does not schedule features in xiiView.

Scene geometry uploads ------------------------------------+
World Spotlights -> SpotShadows snapshot -> ShadowAtlas ----+-> SceneShadowCascade x4
| | (perspective caster views)
+-> opaque local lighting <--------+--- completed atlas
+-> transparent raster <--------------- completed atlas
opaque local potential shadow contribution -> ReactiveLighting union -> TAA
screen-space irradiance ---------------------> ReactiveLighting union

Each reused caster occurrence selects world/tag-authoritative geometry, performs GPU instance/meshlet culling, resets counters, prepares indirect vertex-pull draws and rasterizes the current material/pose into its own atlas rectangle. Casters outside the main camera remain eligible. CascadeIndex selects the occurrence's slot for either snapshot type; the spotlight path uses perspective position, cone rejection and LOD rather than substituting a directional projection. Alpha-masked materials use the existing depth shader's actual texture/cutoff. Transparent meshes remain receivers rather than shadow casters.

The snapshot carries one to four views, a graph-owned 384-byte sampling constant buffer, and a structured SRV receiver table of sorted (object ID, flags) pairs, eight bytes per world instance (one zero sentinel when empty). The atlas is single-sample D32Float with DepthStencil/SRV bindings. At the authored 1,024-pixel tile resolution, one light uses 1,024 squared, two use 2,048 by 1,024, and three or four use 2,048 squared (4/8/16 MiB respectively). Caster writes explicitly precede each subsequent atlas version and both opaque/transparent consumers. Sampling validates the exact dimensions, format, bindings and buffer layouts.

Opaque local lighting resolves receiver flags through the G-buffer's R32UInt ID; transparent lighting carries instance flags through its vertex interface. Both multiply only the matching spotlight's BRDF contribution by four-comparison PCF visibility. Other local lights, ambient illumination and emission retain their contributions. Sampling clamps taps to the selected tile, rejects out-of-frustum coordinates, and applies reversed-Z depth and world/texel normal bias. Scene authors depth bias 0.00005 for this perspective path. Reflected settings retain Enabled, Resolution, MaximumLights, NearPlane and all sampling biases.

Only extracted positive-intensity spotlights with CastShadows participate. ShadowFadeOutRange zero resolves to the light's effective range, as specified by the light component API. Shadows fade over the final twenty percent of the camera/light distance and disappear beyond that range. With no eligible light, or Enabled false, no atlas, sampling buffers or reactive image are produced and the existing unshadowed lighting variant executes. Positive-range cones must be finite, between 1 and 175 degrees, and extend beyond twice NearPlane. More than the authored MaximumLights (at most four), stereo views, missing active resources or oversized device atlas dimensions fail explicitly; no unrelated shadow algorithm or silent light truncation replaces them. Point and area lights remain unshadowed in this workload.

The shadowed opaque shader also writes an optional viewport-sized RGBA16Float SRV/UAV image (eight bytes per pixel). It marks potential incident spotlight contribution before applying visibility, including fully shadowed receivers. TAA therefore rejects stale history on both shadow/light changes and disappearance. The existing RadianceAdd operation now accepts either optional input for the irradiance/reactivity union: neither produces no output, one forwards its handle, and both execute the existing RGBA32Float addition. Forward transparent layers retain their existing conservative history-trust path. Independent pipeline occurrences own configuration and history; recorded callbacks retain snapshots and GAL resources without borrowing the world or operation instance.

SceneSpotShadows/PerspectiveCasterAtlasAffectsIndividualLights compares actual Scene GPU images and buffers. Twenty-six analytical phases cover caster/material and light removal, alpha-mask textures, automatic/explicit shadow fading, main camera cuts, odd resize, reload, a one-pixel viewport and exact restoration. Initially 128 final pixels change; an off-camera caster affects 1,928 shadowed pixels while its identity is absent from the main image. Two independently shadowed lights sum correctly, and four lights exercise every tile in the 2-by-2 atlas with the expected doubled two-light result. Atlas depths, sampling matrices, light indices and receiver records are read back. Every HDR delta equals the measured per-light change; depth, IDs and ambient light match the disabled view. Four transparent phases change 81 layer pixels and 185 final pixels, with no layer change for an unlit receiver or a material that cannot cast shadows. Eleven temporal phases interleave two worlds/four views, verify initialization, cuts, resize, reload and motion, and check 5,415 disappeared interior pixels against a current-frame reference. A recording executes after its world and pipeline instance are destroyed. Active missing atlas/capacity errors fail the view, their explicitly disabled counterparts succeed, and the atlas rejects an actual device-dimension overflow before allocation. Editor's nested override produces the same final pixel changes as Scene and restores output exactly: 128 pixels without screen irradiance, and 312 with irradiance enabled, exercising the combined reactive-input composition.

Windows/MSVC Debug builds pass GraphicsCore, GraphicsCoreTest, GraphicsFoundationTest, EditorFrameworkTest, EditorEngineProcessFrameworkTest and GpuDrivenScene. Complete GraphicsCoreTest (81), Vulkan GraphicsFoundationTest (142) and Vulkan EditorEngineProcessFrameworkTest (76) subtests pass. The final formatted spotlight shaders also pass their focused production GPU run. Production RendererAssets exports all ten sources deterministically on repeated runs, EditorDocuments (20) and NodeLayout (3) pass, and the rebuilt Vulkan Scene sample completes 300 frames. Source asset identities remain stable. Generated pipeline binaries, caches, logs and temporary authoring helpers are excluded.

This is bounded conventional spotlight shadow rendering. Point/area shadows, virtual pages, ray tracing, contact refinement, physical soft penumbrae, animated spotlight-specific acceptance, stereo, large-world budgets and non-Vulkan backends remain unverified or separate work. The conservative reactive path favors correctness over temporal convergence in spotlight-lit regions.

Bloom and metered exposure

The existing Scene display chain is an actual rendering workload. It remains in the canonical resource rather than introducing a second display manager or a subgraph with no additional reusable boundary:

HDRSceneColor -> Luminance Histogram -> Auto Exposure --------+
+-> TAA -> Upscale -> optional Bloom ------------------+-> Tone Mapping -> Grading -> Present
+-----------------------------------+

Histogram input is readable single-sample RGBA; its output is a graph-owned structured 256-uint SRV/UAV buffer (1,024 bytes). The producer clears counters, then counts every input pixel into log-luminance bins. Adaptation validates this exact layout and imports its own two-float SRV/UAV exposure/average-luminance buffer. Valid history is an explicit read-modify-write dependency. Manual mode writes the camera exposure with compensation; automatic mode clips authored percentiles, reconstructs bin centers and adapts toward the metered exposure. Fractional percentile weights remain fractional for one-pixel viewports. First frames do not read uninitialized previous exposure.

Bloom extracts HDR luminance above the reflected threshold with a soft knee and a normalized nine-sample tent footprint at the authored radius. Its RGBA16Float SRV/UAV image follows its authored resolution, input-sized in Scene. With resolved BloomStrength zero, the operation produces no bloom image and records no bloom dispatch. Tone mapping accepts the absent input only at zero strength and uses a zero-weight HDR binding for that shader slot; the shader bypasses its sample. Active missing bloom remains a view failure. These operations validate dimensions, formats, binding flags and dispatch bounds; binding failures report failure before dispatch.

Tone mapping adds bloom to HDR before exposure and maps that result to display-linear color. Existing grading and presentation apply afterward. Controls remain reflected or per-view display settings, and independent occurrences own their configuration/history. This change preserves Scene/Editor identities, existing root interfaces and the nine-source asset library; only Scene's native pin metadata changes to describe optional bloom.

SceneDisplay/BloomAndMeteredExposureAffectProductionOutput exercises actual opaque emissive geometry and production Scene resources. Thirteen bloom phases verify threshold/knee, radius, zero strength, removed content, odd resize, orthographic projection, reload and exact restoration. Initially 784 final pixels change, including 208 pixels outside the bright source. Radius zero removes that halo. Every enabled final RGB value matches measured GPU HDR/bloom inputs, exposure, tone mapping and presentation within output precision. HDR remains identical between enabled and disabled views.

Nine metering phases verify manual/automatic independent views, one-pixel initialization, frozen adaptation, camera cuts, reload, resize and both nonzero adaptation rates against deterministic clock steps. Histogram totals equal the actual pixel count, and presented pixels match the measured exposure. The test reproduced luminance 512 being metered as 425.48 in a one-pixel viewport; corrected fractional weights and bin decoding yield 503.68 within quantization error. Active missing bloom and a four-byte histogram fail the view; zero bloom strength permits the absent bloom input. Editor composition changes 4,780 matching final pixels for bloom and 10,015 for automatic exposure, with exact restoration.

Windows/MSVC Debug builds pass GraphicsCore, both graphics test executables, both Editor test executables and GpuDrivenScene. Complete GraphicsCoreTest (81), Vulkan GraphicsFoundationTest (141) and Vulkan EditorEngineProcessFrameworkTest (76) subtests pass. The strengthened final bloom composition readbacks also pass the focused SceneDisplay run. RendererAssets exports all nine sources deterministically on repeated runs; EditorDocuments (20), NodeLayout (3) and the rebuilt 300-frame Vulkan Scene sample pass. Existing Qt font and unused Vulkan output warnings remain. Generated pipeline binaries, caches and unrelated scene edits are excluded.

This certifies the bounded spatial tent bloom and existing log-histogram exposure path. Multiscale/anisotropic bloom, lens dirt, representative performance, HDR monitor calibration, stereo and other backends remain unverified. Manual exposure still produces the histogram for the existing resource contract; this is not a zero-dispatch manual display path. Arbitrary retained exposure recordings across intervening submissions remain separate acceptance work; existing epoch and world-destruction recording regressions pass.

Ambient visibility

Scene connects its actual depth and material normals to xiiAmbientOcclusionPass with UseRayTracing=false. xiiAmbientOcclusionTemporalPass runs with UseHistory=false to perform only edge-aware spatial filtering. Its StableAO feeds the existing optional Occlusion input of diffuse surface lighting. The normal HDR combination, display operations and Editor composition consume the result. Root outputs retain their contracts; optional AmbientOcclusion exposes the visibility mask for inspection.

Resource Producer and format Consumer
SceneDepth DepthRaster, reversed-Z D32Float at render resolution AO reconstruction and spatial edge rejection
NormalRoughness GBufferRaster, RGBA8UNormalized AO world-space hemisphere sampling
Normal GBufferRaster, RG16SNormalized octahedral normals Spatial edge rejection
RawAO AmbientOcclusion, R8UNormalized SRV/UAV Spatial filter
StableAO Spatial filter, R8UNormalized SRV/UAV DiffuseSurfaceLighting.Occlusion

Both masks are graph transients at the current render resolution. The spatial path allocates no surface history, readiness fences or retained mask images. Sampling uses a fixed spatial phase and reconstructs neighbours at their actual texel centers. The radius is in world units; pixel stride and sample counts control the screen-space search. Scene authors radius 2, pixel stride 2, eight directions, four steps and full spatial weighting. Other tuning remains reflected on the two existing operations.

Setting the AO occurrence's Enabled=false publishes an absent optional mask. The filter emits no work for that absence, and diffuse lighting preserves its unoccluded result. It does not suppress direct lighting, emission or authored material occlusion. R8 storage requires TextureUAVExtendedFormats; an enabled path reports an explicit build failure when that capability is unavailable. An authored disabled occurrence is the supported fallback, with no replacement algorithm selected implicitly.

This integration is screen-space ambient visibility, with the usual missing offscreen and hidden geometry. It is not ray-traced visibility or indirect light transport. Scene deliberately does not use temporal AO yet. Its optional temporal camera now supplies coherent previous-camera matrices and jitter, but the AO history shader still needs jitter/depth reprojection and moving-scene acceptance. Its retained operation has occurrence-local, completion-aware slots and revision-checked recording ownership; that alone does not certify temporal AO.

Vulkan acceptance uses a material-bearing cube contacting a real floor, a world directional light and manual exposure. Full image readbacks compare AO enabled and disabled: depth and direct illumination are identical, ambient diffuse equals the unoccluded result multiplied by the mask, and the HDR delta equals the ambient delta. At 129 by 97, 492 final pixels change and minimum visibility is 189/255. Deleting the occluder restores a neutral mask and identical final images while the second world's contact occlusion remains active. Odd resizing, resource reload, camera-history invalidation and independent views/worlds are exercised.

The canonical Editor GPU regression compares contact pixels with Scene and then disables only its nested AO occurrence, verifying brighter Editor output and an unchanged Scene view. Separate GPU cases execute AO recordings after their pass, views and world are destroyed, reject history promotion after invalidation during setup, and explicitly disable extended storage formats on the device. The latter requires enabled AO to fail diagnostically and disabled AO to build without a mask. Focused captures are SceneAO-Enabled.png, SceneAO-Disabled.png and SceneAO-Mask.png in the test output directory. These are generated evidence, not source assets or cross-backend certification.

The extension passed the Windows/MSVC Debug GraphicsCore and GraphicsFoundation suites, the full EditorEngineProcessFramework suite, EditorDocuments, and the production RendererAssets export fixture on Vulkan. Repeated Scene/Editor exports are byte-identical, their source identities are preserved and no compiled pipeline is tracked. Other backends, representative large-world performance and interactive desktop acceptance remain unverified.

World atmosphere

SceneAtmosphere.xiiRenderPipelineAsset is a reusable physical atmosphere workload, referenced by its source GUID from Scene. Its four operations are world atmosphere constants, transmittance integration, approximate multiple scattering and per-pixel sky/aerial application. Scene supplies the actual depth, opaque HDR, camera snapshot and selected directional illumination. Its output replaces HDR before histogram/exposure, bloom, tone mapping and the public HDRSceneColor interface. Editor consumes this same Scene output before its overlays. Scene's public HDR interface retains its RGBA32Float SRV/UAV contract through an authored requirement on this subgraph occurrence. Other uses of the workload can retain the inactive application's input format.

Resource Format and extent Dependency
AtmosphereConstants Uniform buffer, optional Selected world component and reflected physical settings
Transmittance RGBA32Float, authored 256 by 64 AtmosphereConstants
MultiScatter RGBA32Float, authored 32 by 32 AtmosphereConstants and transmittance SRV
AtmosphereRadiance RGBA32Float at input depth extent when active Both lookup SRVs, camera/environment uniforms, immutable scene depth and radiance

Lookup images declare SRV/UAV usage and remain graph-owned, occurrence-local transients. They regenerate when the workload executes; no global LUT registry or content cache is introduced. Their default image footprint is 272 KiB per active occurrence before graph allocation overhead. Repeated views do not share mutable image contents. The four operations require compute, without mesh shaders or hardware ray tracing.

The constants operation authors UseWorldAtmosphere=true and RequireWorldAtmosphere=true. World extraction and existing priority/stable-ID selection determine its component. With no selected component, or Enabled=false, it publishes no optional constants: both LUT operations emit no work and the application forwards radiance unchanged. Inactive application preserves its input format and resource instead of allocating a replacement. Existing authored fallback behavior remains the default for other uses of the constants operation. Valid constants with a missing or malformed LUT remain an explicit build failure.

Component physical coefficients, planet/up/altitude, sun parameters and sample counts remain reflected. Lookup dimensions and queue selection remain independent pass properties. The implementation integrates Rayleigh/Mie scattering and absorption along sky and geometry segments, with ozone extinction and the existing solar disk. Orthographic cameras use parallel rays from their pixel's camera plane. This path does not supply environment convolution, atmospheric shadows, clouds or participating-volume lighting; approximate multiple scattering and bounded ray marching are explicit quality limits.

Vulkan image acceptance uses a real material-bearing object about one kilometre from the camera and a world directional light. At 65 by 49, atmosphere changes 3,104 sky HDR pixels, all 81 geometry HDR pixels and 1,895 final pixels. Depth and object identities remain identical. No-component, authored disable and component deletion restore exact input/output equality. Tests cover independent worlds and views, physical-setting mutation, odd resizing, camera-history invalidation, orthographic rays, component recreation and continued rendering after another world is destroyed. Reloading the referenced resource changes lookup extents to 65 by 17 and 17 by 9, verifying actual dependency recompilation. Separate checks preserve RGBA16Float on inactive application and reject missing active LUTs. The native Editor test verifies visible sky through its Scene composition and restores its original geometry/background pixels after component deletion.

The production export fixture writes the ordinary file-system asset redirection table RenderPipelines/PipelineLibrary.xiiAidlt beside the generated binaries. The standalone sample mounts that cache/table, so GUID dependencies resolve in a fresh process. Normal Editor/project packaging uses Scene's source-GUID transform and package dependency on SceneAtmosphere; the isolated preview test exercises a project asset table containing both resources. Generated binaries and lookup tables remain outside source control.

Validation passed on Windows/MSVC Debug with Vulkan: all four CTest targets (RendererAssetPreparation, GraphicsCoreTest, GraphicsFoundationTest and EditorEngineProcessFrameworkTest), the EditorDocuments group and focused atmosphere, native transport and Editor view groups. The final public-HDR contract was exported again and exercised through atmosphere readbacks. A separate sample process rendered 300 frames using the generated GUID table, without a world atmosphere component; active sky/aerial output is established by the GPU comparisons above. Initial broad regressions exposed an incomplete preview package and an inconsistent synthetic orthographic transport camera; both fixtures were corrected and passed. Other backends, interactive desktop acceptance and representative performance remain unverified.

Directional shadows

Scene references SceneDirectionalShadows.xiiRenderPipelineAsset with the same selected directional-light snapshot used by illumination. The workload contains cascade preparation, an initialized atlas, four independently configured occurrences of SceneShadowCascade, and directional visibility resolution. Each cascade occurrence authors twelve operations: snapshot-derived visibility/raster constants, LOD initialization, four counter resets, instance culling, meshlet bounds/dispatch, meshlet culling, vertex-pull command generation and ordinary depth rasterization. It reuses the native culling and raster algorithms rather than a shadow renderer manager. Cascades above the active count emit no raster work and forward the atlas.

Resource Format and extent Producer and consumer
Directional light Immutable CPU snapshot World selection supplies illumination and CastShadows intent to cascade preparation
Cascades Immutable CPU snapshot and uniform buffer Stabilized camera/light projection supplies matching culling, raster and sampling data
Candidates, visibility, LOD, indirect commands Structured buffers with explicit SRV/UAV/indirect dependencies Per-cascade selection, existing GPU culling and draw preparation feed depth rasterization
Shadow atlas D32Float, depth/SRV, 2 by 2 tiles for four cascades Atlas clear and ordered cascade raster versions feed visibility sampling
Receiver flags Sorted immutable uint2 buffer, eight bytes per world draw record World GPU identities/flags are copied during setup; per-pixel lookup honors receiver policy
Shadow visibility R32Float at Scene surface extent, SRV/UAV Atlas, depth, normals, object IDs and camera produce the directional illumination multiplier

Defaults are four 1024 by 1024 cascades, 120 metres maximum distance and 50 metres light-space depth padding. The atlas occupies 16 MiB before graph allocation overhead. Extents, splits and padding remain reflected cascade settings. Sampling exposes normalized depth bias, world normal bias and normal bias in shadow-texel units. Four explicit comparison taps provide bilinear PCF, clamped within each tile. The resolution-aware normal offset prevents flat receivers from acquiring self-shadowing when atlas resolution changes. There is no temporal shadow history.

Enabled=false, no directional emitter, zero intensity or the selected emitter's CastShadows=false produces no cascades, atlas or visibility. Directional lighting then retains its original unshadowed behavior. Disabling this feature does not select another shadow algorithm. The canonical vertex-pull path requires compute, bindless resources and indirect draws; it requires neither mesh shaders, extended storage-image formats nor hardware ray tracing. Atlas dimensions are checked against the actual device limit before allocation, including multiplication bounds.

Caster candidates come from world-authoritative extraction with the view's tag selection, not the main camera's compact visible-meshlet list. Shadow frusta include the authored depth padding. Orthographic coverage uses pixels per world metre and conservative meshlet culling without perspective cone rejection. Material shadow flags, transparent exclusion, alpha coverage and the canonical current-pose depth shader remain in the raster path. Each occurrence has separate transient contents. The authored 262,144-meshlet capacity rejects an insufficient conservative world bound before dispatch; it does not silently publish a truncated caster set.

Production Vulkan comparisons cover real box/floor geometry, materials and a world sun, two independent worlds and enabled/disabled views. The initial 129 by 97 case has 305 shadowed pixels and 118 changed final pixels in the first world. A caster outside an orthographic camera's object-ID image changes 741 visible floor pixels. Removing the caster, disabling its material's shadow flag, or disabling the light's shadow flag restores the expected unshadowed output. Depth, object IDs and ambient illumination remain identical between the enabled and disabled views, while direct light is multiplied by the measured mask (within its RGBA16Float rounding).

Tests also change the referenced workload from four 1024-texel cascades to one 512-texel cascade, resize the viewport, reload Scene, invalidate camera history, destroy an independent world and execute a retained canonical recording after its world and pipeline instance are destroyed. The full comparison repeats on a device with mesh shaders and extended storage formats disabled. Editor acceptance compares changed geometry pixels through its existing Scene composition. Ballistic billboard particles

SceneParticles is an independently authored three-operation workload:

World Births -> Ballistic Trajectories -> Append Billboard Layers
seeds + trajectory batches ^ camera, opaque depth
private surface materials --------------+
SceneTransparency raw layers ---------------+ -> shared root OIT resolve -> TAA
Spatial reflection radiance ----------------------^ original HDR input

World Births.Enabled gates the entire particle workload. Disabled upload, absent systems or no live matching births emit no particle buffers; append forwards any existing mesh layers exactly. With neither workload present, the root resolve forwards the original HDR handle. Active rendering requires compute, bindless textures/samplers, five float blend attachments and independent blending. Unsupported active configurations fail explicitly; disabling particle upload is the authored fallback. No mesh-shader or hardware-ray capability is needed.

The world component captures bounded deterministic initial conditions during PostTransform updates, before render extraction. Point, sphere and volume-box emitters support burst and continuous emission, lifetime removal, authored emitter and system capacities, bindings and dropped-spawn counts. CPU birth metadata is not a second evaluation of current particle positions. World-space births preserve the transform at birth; local-space births follow the current owner transform. Paused worlds retain their age and can display an initial burst for Editor preview. Only the world clock advances emission; multiple views cannot advance it twice.

Ballistic Trajectories.Acceleration explicitly selects a world-space analytic trajectory, defaulting to Z gravity. It is a distinct operation from the retained Euler integration pass. Existing graph-runtime allocation/debug-label scheduling is not an implemented particle graph executor. Graphs, force fields, collision, neighbors/molecular simulation, events, readback scheduling and sorting are rejected by this workload. Its billboard renderer is unlit, does not cast shadows and does not substitute for stretched, ribbon, trail, mesh or volumetric renderers.

Billboards use renderer tint/size and canonical base-color/emissive texture and sampler evaluation. Authored materials must explicitly select translucent, additive or modulation blending; absent material selects a white translucent VFX surface. ReceiveLighting and CastShadows must be false. This path does not yet apply atmospheric segment scattering to particles. SoftParticleDistance fades coverage against reconstructed opaque depth. Particles preserve scene depth and ObjectId; Editor mesh picking continues through them. Covered pixels use the shared conservative temporal trust, including rejection after particles disappear.

Each prepared recording owns its seed/batch/material values and GAL pipeline references. Per-occurrence leases retain immutable bindless texture indices and share identical sampler registrations. Reloaded textures receive new indices; previous recordings retain the previous actual views. Retirement uses the active submission frame, which can be newer than the graph's setup frame. Rebuilding a pipeline or destroying its world does not retire a retained recording's resources. There is no cross-view GPU simulation history to initialize on cuts, resize or reload.
