Editor modernization

This is an ongoing migration against the current Engine, not a completed-work report. The authoritative objective is comprehensive Editor and tooling modernization, including integrated workflows and compatibility. Passing library builds alone does not satisfy it.

Native GPU mesh identity for SceneView picking

  • Scene icon captures now use one internal xiiScenePickingReadback transport, which also reads the native packed RGBA32UInt mesh query output. Native owner validation remains with each consumer. Three slot tables pair images with their original metadata; completed slot metadata is consumed before another capture can reserve that slot. Same-frame reservations remain distinct. Reservations from graphs that did not execute are released at the next frame boundary, using the render graph's full 64-bit setup frame identity. Pending captures are drained before resizing or changing formats; no GPU submission or wait occurs in the transport. Overflow checks bound host pixel storage, and view/camera/target snapshots continue to reject stale queries.
  • Windows Debug builds pass for EditorEngineProcessFrameworkTest, EditorEngineProcess and GraphicsCoreTest. All 41 Vulkan engine-process tests and all 18 GraphicsCore tests pass. The native mesh fixture fills all three capture slots, verifies fourth-capture backpressure, and compares asynchronously published packed pixels with GPU readback. Existing icon picking, marquee, resizing, camera/target invalidation and per-view isolation coverage passes through the consolidated transport. Evidence: Workspace/editor-native-picking-readback-build.log, Workspace/editor-native-picking-readback-tests.log and Workspace/editor-native-picking-readback-core-tests.log.
  • Native xiiView projections now consistently use ZeroToOne reversed Z, matching depth prepasses, G-buffer rasterization and surface queries. Core cameras retain their conventional projection contract. Both eyes, including asymmetric stereo matrices, are converted when view matrices are cached. Camera replacement also invalidates caches even if the replacement's modification counters match. xiiViewData query implementation is separated into its own source file: rays start on the near plane and use an interior depth to support infinite far planes. Invalid/non-finite queries return xiiResult failure without changing outputs. Texture preview shaders consume the native projection directly; their previous local depth reversal was removed to preserve nearest cube-sphere coverage.
  • Windows Debug dependent builds pass for GraphicsCoreTest and the engine-process tests. All 18 Core tests and all 41 Vulkan engine-process tests pass, including perspective/orthographic, negative orthographic near planes, asymmetric stereo, infinite far planes, camera replacement and invalid query tests. Native mesh raster readback now uses an actual xiiView projection. Cube preview face and resource reload tests also pass. Evidence: Workspace/editor-native-view-projection-build.log, Workspace/editor-native-view-projection-tests.log and Workspace/editor-native-view-projection-core-tests.log.
  • A dedicated native surface-query raster now consumes the existing compact visibility stream, geometry residency and material tables. It produces one RGBA32UInt target containing native identity, depth bits and oct-encoded smooth geometric normal bits, plus its transient reversed-Z depth buffer. It needs no G-buffer or scene depth prepass. Callers choose transparent visibility separately from the main scene; zero-opacity translucent pixels and masked alpha holes reveal the surface behind them. G-buffer and picking share canonical mesh emission and material coverage shader code. AddPickingPass uses xiiResult, rejects invalid descriptions and clears its output on failure. Shader lifetime remains subsystem-owned; no Editor or Qt dependencies enter GraphicsCore.
  • The Windows Debug engine-process target builds and all 40 Vulkan tests pass after this addition. Actual GPU readback verifies opacity-independent opaque coverage, masked rejection/acceptance, translucent rejection/acceptance and transparent visibility exclusion, including native component resolution and nearest-surface depth. It also verifies the packed normal and invalid inputs. The direct-graph fixture uses its own native completion tracker, independent of the registered graph manager's submission timeline. Evidence: Workspace/editor-native-mesh-query-build.log and Workspace/editor-native-mesh-query-tests.log.
  • The native mesh-shader G-buffer now writes a context-local, generation-checked scene identity. Zero denotes background; application render IDs remain separate user data. This replaces the unused GPU object-index field without changing the GPU record size. Scene hot storage retains handles in place of its alive byte, adding three bytes per allocated object slot. Compaction preserves identity; removal and clearing advance the existing Foundation ID-table generations.
  • Mesh synchronization keys packets by native object/component handles, source render ID and section. Different components or sections with colliding source IDs no longer overwrite one another. Shared geometry and material acquisition remain with the existing managers. Clearing a database also causes stale extraction entries to be retired and recreated on the next synchronization.
  • The world-authoritative migration supersedes the database synchronization and context identity storage described above. xiiGpuInstanceData::Resolve maps non-reused GPU draw IDs to validated world/component handles and mesh sections. The existing render world module owns this derived data, shared by cameras and picking; no separate rendering object lifecycle or hierarchy remains. xiiView::ResolveRenderedMesh also checks active owners and view tags, returns xiiResult, and clears output on failure. Instanced component index shifts invalidate their old GPU identities before extraction runs again.
  • IDs are runtime identities, not asset identifiers. Pair asynchronous readbacks with their producing world/view and validate capture state, camera and resource changes. Resolution requires world read access at the CPU frame boundary. See the migration report for the current ownership, lifecycle, upload and verification contracts.
  • Windows Debug builds pass for GraphicsCoreTest, EditorEngineProcessFrameworkTest, EditorEngineProcess and EditorFrameworkTest. All 18 GraphicsCore tests, all 40 Vulkan engine-process tests and all 6 EditorFramework tests pass. The new test executes native geometry upload, visibility, depth and G-buffer rasterization, reads back the actual R32UInt result, and resolves the visible mesh to its native component. It also checks background zero, colliding component/section IDs, packet retirement, database clearing, invalid contexts and non-extracted scene objects. The initial raster fixture supplied a reversed-Z matrix; it now exercises the native view's projection as described above. Evidence: Workspace/editor-scene-mesh-source-verified-build.log, Workspace/editor-scene-mesh-source-tests.log, Workspace/editor-scene-mesh-source-core-tests.log, Workspace/editor-scene-mesh-source-editor-build.log and Workspace/editor-scene-mesh-source-editor-tests.log.

Native skeleton pose authoring and simulation pullback

  • Native xiiSkeletonPoseComponent now reflects a sparse BoneTransforms map of absolute runtime local transforms, plus its mesh-application setting. Overrides are keyed by joint name, survive skeleton reordering/reload, and leave unknown names available for later resource revisions. Removing an override restores the joint's rest pose. The pose manager also evaluates while simulation is disabled, so document edits reach the native pose without entering play mode.
  • SetLocalPose validates a complete indexed input and binds it to the currently loaded skeleton's names before replacing overrides. Invalid inputs return xiiResult without modifying authored data. Component binary version 2 saves authored overrides; version 1 indexed poses resolve once against their skeleton. Unresolved version 1 data is retained when saving before resource availability. Pose implementation and mesh-palette construction have separate source files.
  • Both native animation and pose components expose evaluated pose snapshots by joint name. Snapshots reject uninitialized poses and changed skeleton revisions, including reloads that preserve joint count. Transforms, names and pose counts are validated before a snapshot is returned. Runtime code has no Qt or exposed bone metadata dependency.
  • Mesh palette mapping moved from preview-only code into GraphicsCore. Native components and previews now share resolution of mesh bone names, palette indices and mesh inverse bind poses. Sparse unused slots are identity; malformed mappings clear the output. Native mesh application reuses palette/scratch capacity and clears failed skinning output without discarding independent morph weights.
  • Bone gizmos resolve the existing asset metadata hierarchy into native coordinates, baking import coordinates into default root joints once and preserving reflected scale signs. Native overrides already include those coordinates. Synthetic import metadata is not exposed as an editable joint. Rotation edits preserve translation and nonuniform scale and insert missing overrides through the command accessor. Manipulators now observe collection insertion/removal as well as value changes. Skeleton curator notifications defer metadata refresh to redraw, with owned event subscriptions. Exposed-bone metadata remains a tooling/asset format, not runtime component storage.
  • Scene simulation pullback uses native component snapshots instead of the removed animation message. IPC carries skeleton identity, and layered scene documents apply transforms only to a matching skeleton component. Failed pose commands cancel the layer transaction. Animated components take precedence over static pose components when collecting an object's pose. Scene context teardown now resets UUIDs using the current API and relies on world-owned registered views rather than the removed per-frame game-state view submission call.

All 6 EditorFramework tests and all 39 Vulkan engine-process tests pass, including real document-to-world pose mirroring, insert/remove undo/redo, simulated curator refresh notifications, skeleton resource reload/reordering, component version 1 loading, version 2 world round trips, IPC serialization and reordered sparse mesh palettes. Baseline and architecture assessment

Baseline: 2ac6681c3 on 2026-10-11, clean worktree. The Windows VS2026 workspace uses Qt 6.11, DLLs, and individual translation units (unity disabled). The attempted Debug build of Editor, EditorEngineProcess, EditorProcessor, and ToolsFoundationTest fails in EditorEngineProcessFramework before higher-level Editor targets compile. The log is Workspace/editor-modernization-baseline.log. Failures include removed render-target types, moved component headers, missing texture utilities, and mismatched reflected enum accessors. These are baseline failures, not regressions from this modernization.

A repository scan covers 984 C++ files in 16 Editor, EditorPlugins, and tooling library modules. It finds 78 unresolved include candidates, including generated Qt UI headers which must not be treated as removed functionality. References include 28 calls to the removed global render world, 7 actor references in a window path already partly migrated to WindowManager, and obsolete pass/extractor property access. Detailed scan evidence is in Workspace/editor-api-inventory.json.

Current Engine boundaries:

  • Core owns worlds, object/component lifetime, resource handles, reflection-based serialization, window registration, and the domain-independent graph.
  • GraphicsFoundation owns GAL resources, command queues, swap chains, texture readback, and device lifetime.
  • GraphicsCore owns world-local xiiRenderWorldModule views, reusable pipeline resources, isolated runtime instances, and specialized render-graph execution.
  • GameEngine supplies window output targets and application orchestration.
  • ToolsFoundation owns document objects, commands, undo/redo, reflected properties, object mirrors, asset-independent serialization, and project infrastructure.
  • GuiFoundation and EditorFramework own Qt presentation, actions, document windows, IPC clients, project UI, asset curation, and authoring services.
  • Engine-process and domain plugins translate authoring state into real Engine objects and resources. They must consume these boundaries rather than restore the removed global renderer, actors, extractors, or render context.

  1. Shared engine-process window, view, thumbnail, reflection-message, and lighting integration. Build its target and test ownership/readback behavior.
  2. EditorFramework, GuiFoundation, project/document services, asset processing, plugin lifecycle, and IPC. Run ToolsFoundation tests and add focused tests for changed invariants.
  3. Scene and asset plugins: world synchronization, view pipelines, picking, gizmos, material/shader tooling, supported graph editors, and preview resources.
  4. Consolidate redundant paths and remove proven obsolete code, build entries, registrations, and UI. Preserve user asset and project formats or add migration.
  5. Build all applicable applications/plugins/tools. Launch Editor and engine process, then verify project open/create, documents save/load, asset browsing and transforms, scene creation and object edits, properties, transforms, selection, viewport resize/rendering, reload, undo/redo, document switching, project close, and shutdown.

Each workflow above remains unverified until it has direct runtime or automated evidence. Linux, macOS, and alternative build configurations require separate verification. This inventory and its remaining gates will be updated as the migration progresses; no requirement is waived because a subsystem is difficult.

Asynchronous Document Save Revisions And Completion Ownership

Accepted asynchronous saves had a separate dirty-state bug. Completion always called SetModified(false), even if a later transaction, undo or redo had changed the document since its snapshot was serialized. The next normal Save could then be a no-op and leave those newer edits absent from disk. Saved-event listeners' edits were also cleared after notification. In addition, every completion invalidated the document's current save handle, so finishing an older request could hide a later queued save from close-time waiting.

Each document now advances a modification revision on every SetModified(true), including calls while it is already dirty. Save construction captures that revision alongside its graphs. Successful completion clears dirty state only when the captured revision is still current, before publishing DocumentSaved. A listener's subsequent edit remains dirty. The existing event facility permits one nested ModifiedChanged notification for this supported listener behavior; deeper recursive notification remains guarded.

Each write task owns its path and result. The worker no longer reads or writes the live document, and the completion task owns the finished write task until its result has been consumed. The old shared m_LastSaveResult was removed. Failed-write messages describe that request's captured path, even when the document path changes before the worker runs. Existing dependencies still serialize queued saves.

Completion only clears the active handle when it still identifies that task, and does so before invoking the callback. It does not access the document after the callback. Close-time waiting drains successor saves queued by completion callbacks. Synchronous Save waits on its own copied task ID, leaves newer handles intact, and revalidates writability after waiting for an earlier callback. Resource documents continue to use their existing metadata preparation and post-save hooks.
